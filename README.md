ระบบจอง Private Gym รายชั่วโมง — หนึ่งการจองได้ใช้ทั้งยิม Trainee จองเองพร้อมชวนเพื่อน
หรือ Trainer จองให้ลูกเทรน ชำระเงินแล้วยืนยันทันที เลื่อน ขอเปลี่ยน Trainer และคืนเงินผ่านแอดมิน

## ธีมและแบรนด์

ฟอนต์ **IBM Plex Sans Thai** (เนื้อความ) คู่กับ **Plus Jakarta Sans** (หัวข้อ)

พาเลตต์เป็น indigo + น้ำเงิน + มิ้นต์ บนออฟไวท์
สีตั้งต้นที่กำหนดไว้คือ `#464b71` `#118ab2` `#7cd5c7` `#f2f2ed`
ส่วนเฉดที่เหลือคำนวณต่อใน OKLCH

ramp หลักของหลังบ้าน (`BrandPalette::Tide`) **ไล่สีสันผ่านทั้งสามสี** แทนที่จะยึดสีสันเดียว
คือเริ่มที่มิ้นต์ในเฉดอ่อน ผ่านน้ำเงินตรงกลาง แล้วจบที่ indigo ในเฉดเข้ม
ทำให้ไล่เฉดใช้สีของแบรนด์ได้ครบทั้งชุด

| โทเคน | ค่า | ใช้ทำอะไร |
|---|---|---|
| `ink` / `muted` | `#292c41` / `#616471` | ตัวอักษรหลัก / ตัวอักษรรอง |
| `brand-light` | `#7cd5c7` | มิ้นต์ เน้นข้อความบนพื้นเข้ม |
| `brand` / `brand-deep` | `#118ab2` / `#00749a` | น้ำเงิน ลิงก์และจุดบอกสถานะ |
| `brand-dark` / `brand-deepest` | `#464b71` / `#272b49` | indigo พื้นหลังส่วนหัวและปุ่มหลัก |
| `accent-light` / `accent` / `accent-deep` / `accent-ink` | `#f9e5c7` / `#deae67` / `#bd8638` / `#96621e` | อำพัน ใช้กับสถานะที่ต้องเตือน |
| `paper` / `mist` / `line` | `#f2f2ed` / `#e3f0ee` / `#d3dddb` | พื้นหลังและเส้น |
| `track` | `#e8e8e4` | แถบที่ยังไม่ถูกใช้ เช่นช่องที่นั่งว่าง |

โทน `accent` ไม่ได้อยู่ในสี่สีที่กำหนดมา แต่จำเป็นต้องมี เพราะสีที่กำหนดเป็นโทนเย็นทั้งหมด
จึงไม่มีสีไหนที่ผู้ใช้อ่านออกว่าเป็นคำเตือน

หน้าบ้านใช้โทเคนเหล่านี้ผ่าน `tailwind.config.js` ส่วนหลังบ้านใช้ `app/Support/BrandPalette.php`

**ถ้าจะเปลี่ยนพาเลตต์อีก** ต้องแก้ให้ครบทั้ง 5 จุด ไม่งั้นจะมีสีเก่าหลงเหลือ:
`tailwind.config.js` · `resources/css/app.css` (ตัวแปร `:root`) · `app/Support/BrandPalette.php`
(ramp ของ Filament) · ค่าสีที่ฝังตรงในไฟล์ SVG กับไล่เฉด (โลโก้, `public/favicon.svg`,
คลื่นใน `layouts/auth`, hero ของแต่ละหน้า) · `theme-color` ใน `partials/head.blade.php`

**ทำไมไม่ใช้ `Color::hex()` ของ Filament:** ตัวสร้างพาเลตต์อัตโนมัติเร่งความอิ่มสีจนได้ chroma
สูงกว่าสีจริงของแบรนด์หลายเท่า ทำให้หลังบ้านดูสดผิดโทนเมื่อเทียบกับหน้าบ้าน
`BrandPalette` จึงกำหนด ramp แบบ OKLCH เองโดยยึดสีที่กำหนดไว้เป็นหมุด

สีสถานะก็คุมความอิ่มสีให้อยู่ระดับใกล้เคียงกัน: `Leaf` สำหรับสำเร็จ (เขียวเข้มกว่าเซจของแบรนด์
เพื่อให้แยกออก) `Gold` สำหรับเตือน และ `Clay` สำหรับอันตราย

### หน้า auth (login / สมัคร / เข้าร่วมทีม)

ทั้งสามหน้าใช้ `resources/views/layouts/auth.blade.php` ร่วมกัน เป็นเลย์เอาต์สองคอลัมน์
ฝั่งซ้ายเป็นแผงแบรนด์ (ซ่อนต่ำกว่า `lg`) ฝั่งขวาเป็นฟอร์ม แต่ละหน้าส่งข้อความของตัวเองเข้ามา
ผ่าน `->layout('layouts.auth', [...])`

**เส้นแบ่งแบบคลื่น** เป็น SVG สามชั้นที่เลื่อนขึ้นด้วยความเร็วต่างกันเพื่อให้เกิดมิติ
เส้นคลื่นถูกวาดยาวเกินกรอบทั้งบนและล่าง และแอนิเมชันเลื่อนขึ้นครบ 1 รอบพอดี (400 หน่วยใน viewBox)
ภาพจึงต่อกันสนิทและวนได้โดยไม่เห็นรอยต่อ — ถ้าจะแก้ค่ารอบ ต้องแก้ทั้งใน path และใน
`@keyframes wave-scroll` ให้ตรงกัน ไม่งั้นจะเห็นภาพกระตุกทุกครั้งที่วนรอบ

`main` ของเลย์เอาต์นี้ต้องมี `overflow-x-hidden` เสมอ เพราะก้อนแสงตกแต่งล้นขอบขวา
ถ้าเอาออกจะเกิดแถบเลื่อนแนวนอนบนจอเล็ก

**สมัครเทรนเนอร์เป็น wizard 3 ขั้น** (`App\Livewire\TrainerRegistration`) ตรวจทีละขั้นด้วย
`rulesForStep()` และตรวจทั้งหมดอีกครั้งตอนกดสมัคร ผู้ใช้ย้อนกลับไปขั้นที่ผ่านมาแล้วได้
แต่กระโดดข้ามไปข้างหน้าไม่ได้ ส่วนมาตรวัดความแข็งแรงรหัสผ่านคำนวณฝั่งเบราว์เซอร์ด้วย Alpine
เพื่อให้เห็นผลทันทีขณะพิมพ์ ไม่ต้องวิ่งไปเซิร์ฟเวอร์

ทุกแอนิเมชันมี `@media (prefers-reduced-motion: reduce)` ปิดให้อัตโนมัติ

### กล่องยืนยันและการแจ้งผล

**ห้ามใช้ `wire:confirm` หรือ `confirm()` ของเบราว์เซอร์** ทั้งโปรเจกต์ใช้กล่องยืนยันของแอปเอง
(`resources/views/components/app-dialog.blade.php`) ซึ่งผูกอยู่กับ `layouts/app` อยู่แล้ว
ตัว store ลงทะเบียนใน `resources/js/app.js` ไม่ใช่ในหน้า เพราะหน้าแรกหลัง login เข้ามาด้วย `wire:navigate`

```blade
<button @click="$store.confirm.ask({
    title: 'ลบกลุ่มนี้',
    body: 'กลุ่มเช้า · 4 คน',
    notes: ['ลูกทีมยังอยู่ในทีมตามเดิม'],
    tone: 'danger',
    action: () => $wire.deleteGroup(12),
})">ลบ</button>
```

`notes` มีไว้บอกผลกระทบที่ผู้ใช้ควรรู้ก่อนกดยืนยัน
ซึ่ง `confirm()` ของเบราว์เซอร์ทำไม่ได้

**การแจ้งผลใช้ toast ไม่ใช่ flash message** ฝั่ง Livewire เรียก
`$this->dispatch('toast', tone: 'success', title: '...', body: '...')`
โดย `tone` รับค่า success / error / warning / info ฝั่ง JS ล้วนๆ ก็ยิง
`window.dispatchEvent(new CustomEvent('toast', { detail: {...} }))` ได้เหมือนกัน

### ชื่อผู้ใช้

ตาราง `users` เก็บ `first_name` กับ `last_name` แยกกัน ส่วน `name` เป็น
**stored generated column** ที่ MySQL คำนวณให้เองจากสองคอลัมน์นั้น

```sql
name  VARCHAR(255)  GENERATED ALWAYS AS (TRIM(CONCAT_WS(' ', first_name, last_name))) STORED
```

เลือกวิธีนี้แทนการทำ accessor ใน PHP เพราะยังค้นหาและเรียงลำดับด้วย `name` ใน SQL ได้ตรงๆ
(Filament ใช้ความสามารถนี้) และไม่ต้องเขียนโค้ดซิงก์เอง

**`name` เขียนไม่ได้** ถ้าโค้ดไหนพยายาม `update(['name' => ...])` MySQL จะโยน error ทันที
ให้เขียนที่ `first_name` / `last_name` แทน มีเทสต์ใน `tests/Feature/UserNameTest.php` คุมไว้

### QR เข้าร่วมทีม

สร้างเองด้วย `App\Support\QrCode` (bacon/bacon-qr-code) เป็น SVG ฝังในหน้าเลย
ตั้งใจไม่เรียกบริการสร้าง QR ภายนอก เพราะลิงก์คำเชิญไม่ควรถูกส่งออกไปให้บุคคลที่สาม
และหน้าเว็บไม่ควรพังเมื่อบริการนั้นล่ม

### มือถือ

ทุกหน้าผ่านเกณฑ์: ไม่มีการเลื่อนแนวนอน และปุ่ม/ช่องกรอกที่กดได้มีความสูงอย่างน้อย 44px
ถ้าเพิ่มองค์ประกอบตกแต่งที่ล้นขอบ (เช่นก้อนแสงเบลอ) ต้องใส่ `overflow-hidden`
ให้กล่องที่ครอบมันเสมอ ไม่งั้นจะเกิดแถบเลื่อนแนวนอนบนจอเล็ก

**ทำไมไม่ใช้ `Color::hex()` ของ Filament:** ตัวสร้างพาเลตต์อัตโนมัติเร่งความอิ่มสีจนได้ chroma ราว 0.17
ขณะที่สีจริงของแบรนด์อยู่แค่ราว 0.07 ทำให้หลังบ้านดูสดกว่าเว็บหลักอย่างเห็นได้ชัด
`BrandPalette` จึงกำหนด ramp แบบ OKLCH เองโดยยึดสีจริงเป็นหมุด

## โจทย์หลักที่ระบบนี้แก้

ระบบจอง **Private Gym รายชั่วโมง** ตามเอกสาร "ข้อกำหนดระบบจอง Hybrid SSW"

- **หนึ่งการจองได้ใช้ทั้งยิม** ช่วงละ 1 ชั่วโมง จองหลายชั่วโมงต่อเนื่องได้ ผู้เข้าร่วม 1–6 คน ไม่นับ Trainer
- ทุกการจองต้องมี Trainer เว้นแต่แอดมินให้สิทธิ์ "เข้าใช้โดยไม่มี Trainer" ไว้ (เก็บประวัติว่าใครให้ เมื่อไร เพราะอะไร)
- จองล่วงหน้าได้ 45 วัน จองได้จนถึงเวลาเริ่ม ยิม Trainer และผู้เข้าร่วมห้ามมีเวลาซ้อนกัน
- Trainer ตั้งเวลาว่างเอง ไม่ต้องกดรับงาน และลบเวลาว่างที่มีคนจองไว้แล้วไม่ได้
- ผู้ชำระเงินจ่ายเต็มจำนวนคนเดียว ระบบกันเวลาไว้ 30 นาที ยืนยันการจองเมื่อชำระสำเร็จ ไม่ชำระก็หมดอายุและคืนเวลา
- เลื่อนเองได้ก่อน 00.00 น. ของวันใช้งาน หลังจากนั้นส่งคำขอให้แอดมิน ราคาเท่าเดิม
- Trainer ขอยกเลิกการรับงานได้ แอดมินเลือกคนแทน แอดมินยกเลิกการจองได้พร้อมคืนเงินเต็มจำนวนให้ผู้ชำระเดิม
- รองรับหลายสาขา ตั้งราคา จำนวนคน และระยะจองล่วงหน้าแยกรายสาขาได้

ระบบ Class (ข้อ 11 ในเอกสาร) ยังไม่ได้ทำ เป็นงานในอนาคต

```bash
php artisan storage:link            # ให้รูปโปรไฟล์ใน storage เปิดผ่านเว็บได้

npm run build                       # หรือ npm run dev ระหว่างพัฒนา

```

บัญชีตัวอย่างจาก `DatabaseSeeder` ใช้รหัส `password` ทุกบัญชี

## ขึ้นเซิร์ฟเวอร์จริง

ความต้องการขั้นต่ำ: **PHP 8.4.1** (ต้องมี `ext-intl` สำหรับรูปแบบเงินบาทและวันที่ภาษาไทย),
MySQL 8, Composer, Node 20+ สำหรับ build ไฟล์ครั้งเดียว

### ครั้งแรก

```bash
git clone <repo> hybridssw && cd hybridssw

cp .env.example .env
# แก้ .env: APP_ENV=production, APP_DEBUG=false, APP_URL=https://โดเมนจริง

composer install --no-dev --optimize-autoloader
npm ci && npm run build

php artisan key:generate
php artisan migrate --force
php artisan db:seed --class=ProductionSeeder --force   # สาขาแรก + บัญชีแอดมิน ไม่มีข้อมูลตัวอย่าง
php artisan storage:link
php artisan filament:assets

php artisan config:cache
php artisan route:cache
php artisan view:cache
```

จากนั้น **ลบ `ADMIN_PASSWORD` ออกจาก .env** แล้วเข้า `/admin` ไปตั้งค่าสาขา
เทมเพลตตาราง และแพ็กเกจต่อ

### ทุกครั้งที่ deploy รอบถัดไป

```bash

npm ci && npm run build
```

> รุ่นที่ต้องการ `>=8.4.1` ตัวเลขที่ใช้ได้จริงจึงเป็น 8.4.1 ขึ้นไป
> รันบน PHP ต่ำกว่านั้นจะถูกปฏิเสธตั้งแต่ `vendor/composer/platform_check.php`
> ถ้าจำเป็นต้องลงบนเครื่องที่มีแค่ 8.2 หรือ 8.3 ต้องรัน `composer update` ใหม่
> บนเครื่องที่ใช้ PHP รุ่นนั้น เพื่อให้ Composer เลือกแพ็กเกจรุ่นที่รองรับ

### Deploy บน Windows + Plesk ด้วยสคริปต์

หลังติดตั้งครั้งแรกเสร็จ (`.env`, ฐานข้อมูล, document root) การอัปเดตทุกครั้งใช้คำสั่งเดียว

```powershell
cd C:\Inetpub\vhosts\srisawan.com\hybridssw.srisawan.com\app
powershell -ExecutionPolicy Bypass -File deploy\deploy.ps1
```

สคริปต์ทำตามลำดับนี้ และเก็บ log ทุกครั้งไว้ที่ `deploy\logs`

1. หา PHP 8.4 ของ Plesk เอง ไม่ใช้ `php` ใน PATH ที่อาจเป็นรุ่นเก่า
2. ถ้าไม่มีโค้ดใหม่ก็ไม่ทำอะไร ถ้ามีไฟล์ถูกแก้บนเซิร์ฟเวอร์ตรง ๆ จะหยุดก่อน ไม่ทับให้
3. ปิดเว็บชั่วคราว → `git pull` → `composer install` เฉพาะตอน `composer.lock` เปลี่ยน
   → `npm run build` เฉพาะตอนไฟล์หน้าเว็บเปลี่ยน → `migrate --force` → `optimize`
4. **เปิดเว็บกลับเสมอ** แม้ขั้นไหนพัง เว็บจะไม่ค้างหน้าปิดปรับปรุง
5. จบด้วย `php artisan gym:doctor` บอกว่าระบบพร้อมให้จองหรือขาดอะไร

ครั้งแรกเติม `-InstallScheduler` ให้ตั้ง Windows Scheduled Task รัน `schedule:run` ทุกนาทีให้ด้วย
ระบบไม่มีงานเข้าคิว (queue) จึงไม่ต้องตั้ง worker แยก

| ตัวเลือก | ใช้เมื่อ |
|---|---|
| `-InstallScheduler` | ครั้งแรก หรือเมื่อย้ายโฟลเดอร์แอป |
| `-Force` | อยากให้รันทุกขั้นใหม่แม้ไม่มีโค้ดใหม่ เช่นหลังแก้ `.env` |
| `-SkipBuild` | ไม่ต้อง build ไฟล์หน้าเว็บ |
| `-Php <path>` | ใช้ PHP ตัวอื่นที่ไม่ใช่ PleskPHP84 |

### ถ้าเซิร์ฟเวอร์เป็น Windows + IIS

IIS ไม่อ่าน `.htaccess` ใช้ `public/web.config` ที่มีมาให้ในโปรเจกต์แทน
ต้องติดตั้ง **URL Rewrite Module** ของ IIS ก่อน ไม่งั้นทุก URL นอกจากหน้าแรกจะ 500

- PHP ต้องเป็นรุ่น **NTS (Non-Thread-Safe) x64** เพราะ IIS ต่อผ่าน FastCGI
- เปิด extension ใน `php.ini`: `intl` `mbstring` `openssl` `pdo_mysql` `fileinfo` `curl` `zip` `gd`
- ตั้ง `cgi.fix_pathinfo=1` และ `fastcgi.impersonate=1`
- Physical path ของ site ต้องชี้ที่ `public\` เท่านั้น
- ให้สิทธิ์ Modify แก่ `IIS AppPool\<ชื่อ pool>` บน `storage\` และ `bootstrap\cache\`
- `php artisan storage:link` ต้องรันจาก PowerShell ที่เปิดแบบ Run as administrator
  เพราะการสร้าง symlink บน Windows ต้องใช้สิทธิ์ผู้ดูแล
- แทน cron ให้ใช้ Task Scheduler รัน `php artisan schedule:run` ทุก 1 นาที
- แทน supervisor ให้ทำ queue worker เป็น Windows Service ด้วย NSSM

### สิ่งที่ต้องตั้งเพิ่มบนเซิร์ฟเวอร์

**เว็บเซิร์ฟเวอร์** ชี้ document root ไปที่ `public/` เท่านั้น
และให้ `storage/` กับ `bootstrap/cache/` เขียนได้โดยผู้ใช้ของ PHP-FPM

**ตัวจับเวลา** — ปิดรายการรอชำระที่หมดเวลาแล้ว และแจ้งผู้ชำระเงิน ทุก 1 นาที
ถ้าไม่ได้ตั้งไว้ การจองใหม่ยังปล่อยเวลาที่ค้างให้เองได้ แต่สถานะบนหน้าเว็บจะค้างเป็น "รอชำระเงิน"
ต้องมี cron บรรทัดเดียวนี้ (Windows ใช้ `deploy.ps1 -InstallScheduler`)

```cron
* * * * * cd /path/to/hybridssw && php artisan schedule:run >> /dev/null 2>&1
```

**คิวงาน** — ไม่ต้องมีตัวรันคิว แจ้งเตือนส่งทันทีตอนเกิดเหตุการณ์ ส่งอีเมลไม่สำเร็จจะบันทึกลง log
แต่ไม่ทำให้การจองหรือการชำระล้ม

**เวลาและภาษา** — `APP_TIMEZONE=Asia/Bangkok` และ `APP_LOCALE=th` ต้องตรงกับในฐานข้อมูล
ไม่งั้นเวลารอบจะเพี้ยนข้ามวัน

### ฐานข้อมูล

โครงสร้างทั้งหมดอยู่ใน `database/migrations` ไม่ต้องนำเข้าไฟล์ dump
เซิร์ฟเวอร์ใหม่รัน `migrate --force` แล้วได้โครงครบทันที

มีสอง seeder ที่ทำคนละหน้าที่

| Seeder | ใช้เมื่อไร | สร้างอะไร |
|---|---|---|
| `DatabaseSeeder` | เครื่องพัฒนาเท่านั้น | สาขาที่ตั้งราคาแล้ว เวลาเปิด Trainer ที่มีเวลาว่าง ลูกทีม และกลุ่มตัวอย่าง รหัสผ่าน `password` |
| `ProductionSeeder` | เซิร์ฟเวอร์จริง | สาขาแรก (ยังไม่ตั้งราคา) กับบัญชีแอดมินหนึ่งคน อ่านรหัสจาก `.env` รันซ้ำได้ไม่สร้างซ้ำ |

## สิ่งที่ห้ามแก้โดยไม่เข้าใจ

### 1. การกันจองซ้อนอยู่ที่ฐานข้อมูล

ตาราง `slot_locks` มี unique key `(resource, resource_id, slot_start)` หนึ่งแถวต่อหนึ่งชั่วโมงต่อหนึ่งสิ่ง
คือยิม (`gym` + branch_id) Trainer (`trainer`) และผู้เข้าร่วมแต่ละคน (`member`)
การจองหนึ่งรายการใส่แถวครบทุกชั่วโมงในทรานแซกชันเดียว ถ้ามีคนจองตัดหน้าในเสี้ยววินาที
ฐานข้อมูลปฏิเสธด้วย duplicate key และ `ReservationService` แปลงเป็นข้อความที่อ่านเข้าใจ

**ห้ามตรวจว่าว่างด้วยการนับแถวแล้วค่อยบันทึก** การตรวจใน `Availability` มีไว้แสดงผลและให้ข้อความดี
ตัวกันจริงคือ unique key นี้ รายการรอชำระที่หมดเวลาแล้วถือว่าว่าง และถูกปล่อยก่อนใส่ล็อกใหม่เสมอ

### 2. เวลาเปิดและเวลาว่างของ Trainer

1. `schedule_templates` — เวลาเปิดให้จองประจำสัปดาห์ของสาขา
2. `schedule_exceptions` — ปิดทั้งวัน เปลี่ยนเวลา หรือเปิดเพิ่ม ทับกฎข้างบน
3. `trainer_availabilities` / `trainer_time_offs` — เวลาว่างและวันลาที่ Trainer ตั้งเอง

`OpeningHours` แบ่งเวลาเปิดเป็นช่องละ 1 ชั่วโมงนับจากเวลาเปิด ไม่มีการสร้างรอบล่วงหน้าเก็บไว้
ปิดหรือลดเวลาเปิดไม่ยกเลิกการจองที่มีอยู่แล้วให้อัตโนมัติ แอดมินต้องจัดการเองที่หน้าการจอง

### 3. การชำระเงินไม่เชื่อ webhook และบันทึกซ้ำไม่ได้

- `payments` มี unique `(provider, provider_charge_id)` ผลชำระเดียวกันมาสองรอบก็บันทึกครั้งเดียว
- webhook ของ Omise ไม่ถูกเชื่อเลย ตัวรับดึง charge จาก Omise ด้วย secret key มาตรวจเองทุกครั้ง
- จ่ายหลังหมดเวลา: ถ้ายังจองเวลาเดิมได้จะยืนยันให้ ถ้าเวลาถูกจองไปแล้วจะไม่แย่งคืน
  แต่ทำเครื่องหมาย "ต้องตรวจสอบ" ให้แอดมินคืนเงินจากหน้า **การชำระเงิน**

### 4. Blade: ใช้ php แบบบรรทัดเดียวเท่านั้น

`@php(...)` กับรูปแบบบล็อกปนกันในไฟล์เดียวไม่ได้ Blade จับคู่ด้วย regex แบบ non-greedy แล้วจะคอมไพล์ผิด

### ไอคอนต้องเรียกด้วย `@svg()` เท่านั้น ห้ามใช้ `<x-lucide-xxx />`

Blade Icons คืนค่าเป็นข้อความ SVG ไม่ใช่ชื่อ view เมื่อเขียนเป็นคอมโพเนนต์
Laravel จะเผื่อไว้ว่าข้อความนั้นอาจเป็นชื่อ view แล้วเรียก `file_exists()` ตรวจดูก่อน

บนเครื่องที่ตั้ง `open_basedir` ไว้ เช่นเซิร์ฟเวอร์ Plesk การเรียก `file_exists()`
ด้วย path ที่ไม่ถูกต้องไม่ได้คืนค่า false เฉย ๆ แต่กลายเป็น warning ที่ Laravel
แปลงเป็น exception ทุกหน้าที่มีไอคอนจึงตอบ 500 ทั้งที่บนเครื่องพัฒนาไม่มีปัญหา

`@svg('lucide-x', 'h-4 w-4', ['stroke-width' => '2.2'])` คืนอ็อบเจกต์ `Svg`
ที่เป็น `Htmlable` ไม่ผ่านการตรวจชื่อ view เลย จึงไม่ชนกับ `open_basedir`

### ตัวกรองใน Filament ต้องตั้งชื่อพารามิเตอร์ว่า `$query`

Filament ส่งค่าเข้า closure ตาม **ชื่อพารามิเตอร์** ไม่ใช่ตามลำดับ
`->query(fn (Builder $q) => ...)` จะได้ query เปล่าที่ไม่ใช่ของตาราง ไม่ใช่ query ที่ต้องการ

ผลมีสองแบบและอันตรายทั้งคู่ ตัวกรองที่ใช้ `whereHas` จะทำให้หน้าพัง 500 ทันทีที่เปิดใช้
ส่วนตัวที่ใช้ `where` ธรรมดาจะไม่พังแต่ **ไม่กรองอะไรเลย** แอดมินจะเห็นข้อมูลทั้งหมดโดยไม่รู้ตัว
เคยเป็นแบบนี้พร้อมกันหกตัว `tests/Feature/AdminFiltersTest.php` สแกนโค้ดกันไว้แล้ว

### `config/app.php` ต้องอ่าน timezone จาก env เสมอ

โครงตั้งต้นของ Laravel เขียน `'timezone' => 'UTC'` ไว้ตายตัว ทำให้ `APP_TIMEZONE`
ใน `.env` ไม่มีผลอะไรเลย ระบบนี้คิดเวลาผิดไป 7 ชั่วโมงทันที เวลาที่เลยไปแล้ว
ยังจองได้ต่ออีก 7 ชั่วโมง และเวลาใน log ไม่ตรงกับนาฬิกาจริง

`tests/Feature/TimezoneTest.php` คุมไว้แล้ว ถ้าใครเผลอเขียนค่าตายตัวกลับไปจะเทสต์ไม่ผ่าน

## เทรนเนอร์ 2 ประเภทต่างกันอย่างไร

| | ภายใน | ภายนอก |
|---|---|---|
| การอนุมัติ | อัตโนมัติ (ต้องมีรหัสพนักงาน) | แอดมินตรวจเอกสารก่อน |
| ขนาดทีม | ไม่จำกัด | 20 |
| ใบรับรอง | ไม่บังคับ | บังคับ หมดอายุแล้วถูกบล็อกทันที |

ค่าในตารางเป็น **ค่าเริ่มต้นที่ตั้งได้ใน `config/gym.php`** (ผ่าน `.env`) ไม่ได้ฝังไว้ในโค้ด
และแอดมินยังตั้งทับรายคนได้อีกชั้นที่หน้าแก้ไขเทรนเนอร์

```
GYM_EXTERNAL_MAX_TEAM=20      GYM_INTERNAL_MAX_TEAM=      # เว้นว่าง = ไม่จำกัด
```

รับงานจองได้เมื่ออนุมัติแล้ว เปิดรับงานอยู่ สัญญายังมีผล และใบรับรองยังไม่หมดอายุ (`Trainer::canTakeReservations()`)

**`max_team_size` เป็น null แปลว่าไม่จำกัด** `Trainer::maxTeamSize()` จึงคืน `?int`
ถ้าเขียนโค้ดที่เทียบกับค่านี้ ต้องเช็ค null ก่อนเสมอ ไม่งั้นทีมไม่จำกัดจะถูกบล็อกทันที
ใช้ `hasUnlimitedTeam()` กับ `teamLimitLabel()` ช่วยได้

## ตัวเลือกของหน้าสมัครเทรนเนอร์

```
GYM_REGISTRATION_SHOW_BRANCH=true       # แสดงตัวเลือกสาขา
GYM_REGISTRATION_VERIFY_IDENTITY=true   # บังคับยืนยันตัวตน
```

**ตัวเลือกสาขา** ปิดแล้วจะไม่แสดง และระบบผูกสาขาที่เปิดใช้งานอันแรกให้อัตโนมัติ
นอกจากนี้ถ้ามีสาขาเดียวก็ไม่แสดงอยู่แล้วถึงจะเปิดค่านี้ไว้

**การยืนยันตัวตน** ปิดแล้วขั้นตอนที่ 3 จะหายไปทั้งขั้น เหลือ 2 ขั้น
และ **เทรนเนอร์ภายในจะไม่ถูกอนุมัติอัตโนมัติอีกต่อไป** เพราะไม่มีอะไรยืนยันว่าเป็นพนักงานจริง
ทุกคนจะเข้าคิวรอแอดมินตรวจแทน — จุดนี้สำคัญ ถ้าปล่อยให้อนุมัติอัตโนมัติทั้งที่ไม่ตรวจอะไรเลย
ใครก็สมัครเป็นเทรนเนอร์ภายในแล้วจองได้ทันที

ในหน้าสมัคร **เทรนเนอร์ภายนอกแสดงเป็นลำดับแรก** เพราะเป็นกลุ่มที่สมัครเองเป็นหลัก
(`TrainerType::orderedForRegistration()` ส่วนหลังบ้านยังใช้ลำดับปกติของ enum)

## หน้าหมดอายุ (419)

หน้าที่เปิดค้างไว้นานจนเซสชันหมดอายุ แล้วกดส่งฟอร์ม เดิมจะเจอหน้า `419 PAGE EXPIRED` เปล่าๆ
ซึ่งผู้ใช้ไม่รู้ว่าต้องทำอะไรต่อ ตอนนี้ `bootstrap/app.php` จับไว้แล้วโยนกลับหน้าเดิม
พร้อมข้อความให้กดส่งอีกครั้ง และคงค่าที่กรอกไว้ (ยกเว้นรหัสผ่าน)

## หน้าจองยิม

`/member/book` (Trainee) กับ `/trainer/book` (Trainer) ใช้คอมโพเนนต์เดียวกัน `Reservations\BookingWizard`

1. เลือกวัน (ภายในระยะจองล่วงหน้าของสาขา) และจำนวนชั่วโมง
2. เลือกเวลาเริ่ม แสดงเฉพาะช่วงที่ยิมว่างครบทุกชั่วโมง ฝั่ง Trainer กรองเฉพาะเวลาที่ตัวเองว่างด้วย
3. ผู้เข้าร่วม: Trainee อยู่ในกลุ่มเสมอ เพิ่มเพื่อนด้วย **รหัสสมาชิกหรือเบอร์โทรที่ตรงทุกตัวเท่านั้น**
   ระบบไม่มีรายชื่อสมาชิกให้เลือก ฝั่ง Trainer แตะเพิ่มลูกทีมหรือทั้งกลุ่มได้
4. Trainee เลือก Trainer จากคนที่ว่างครบช่วง ("ไม่ใช้ Trainer" ขึ้นเฉพาะกลุ่มที่มีสิทธิ์)
5. เลือกผู้ชำระเงินหนึ่งคนจากผู้เข้าร่วม แล้วไปหน้าการจอง `/reservations/{เลขการจอง}` เพื่อชำระ

หน้าตัดสินอะไรเองไม่ได้ ทุกกฎอยู่ใน `ReservationService` ถ้ามีคนจองตัดหน้า หน้าจะแสดงเหตุผลแทนการพัง

## กลุ่มลูกทีม

เทรนเนอร์สร้างกลุ่มเองได้ที่ `/trainer/team` เช่น "กลุ่มเช้า จ-พ-ศ" แล้วแตะเพิ่มทั้งกลุ่ม
เข้าการจองเดียวได้จากหน้าจองให้ลูกเทรน

**จำนวนสมาชิกสูงสุดต่อกลุ่มเป็นของแอดมิน เทรนเนอร์แก้ไม่ได้**

| ระดับ | ตั้งที่ไหน | ผล |
|---|---|---|
| ทั้งสาขา | หน้าแก้ไขสาขา → `จำนวนลูกทีมสูงสุดต่อกลุ่ม` | เพดานเริ่มต้นของทุกกลุ่มในสาขา |
| รายกลุ่ม | หน้า `กลุ่มลูกทีม` ในหลังบ้าน → `จำกัดเฉพาะกลุ่มนี้` | ตั้งทับเฉพาะกลุ่มนั้น เว้นว่าง = ใช้ค่าของสาขา |

หลังบ้าน **สร้างกลุ่มเองไม่ได้และลบไม่ได้** ทำได้แค่ตั้งเพดานและเปิด/ปิดกลุ่ม
ตรงตามหลักที่ว่าหน้าบ้านคือที่ทำงาน หลังบ้านคือที่ตั้งค่า

กติกาอยู่ใน `App\Services\MemberGroupService` ทั้งหมด:

- สมาชิกกลุ่มต้องอยู่ในทีมของเทรนเนอร์คนนั้นก่อน
- เพิ่มเกินเพดานไม่ได้ (ล็อกแถวกลุ่มก่อนนับ กันการเพิ่มพร้อมกันทะลุเพดาน)
- ลูกทีมอยู่ได้หลายกลุ่ม แต่ซ้ำกลุ่มเดิมไม่ได้
- เทรนเนอร์แตะกลุ่มของคนอื่นไม่ได้
- ลบกลุ่มแล้วลูกทีมยังอยู่ในทีมตามเดิม และการจองที่ทำไปแล้วไม่ถูกกระทบ

ตอนแตะเพิ่มทั้งกลุ่ม ระบบข้ามคนที่อยู่ในการจองแล้วหรือยังเพิ่มไม่ได้ ถ้ากลุ่มมีคนเกินจำนวนต่อการจอง
จะเพิ่มเท่าที่ใส่ได้และบอกว่าเพิ่มได้กี่คน

## กราฟิกตกแต่ง

ชุดอุปกรณ์ซ้อมใน `resources/views/components/station-icon.blade.php` และไฟล์เดี่ยวที่
`public/img/stations/*.svg` (9 ชิ้น รวม 36 KB)

```blade
<x-station-icon name="kettlebell" class="h-7 w-7 text-brand-dark" />
```

ชื่อที่ใช้ได้: `ski` `sled` `rower` `kettlebell` `dumbbell` `sandbag` `wallball` `box` `stopwatch`
ใช้ `currentColor` จึงเปลี่ยนสีตามบริบทที่วางได้เลย

วางไว้ 3 จุดเท่านั้น ตั้งใจไม่ใส่เยอะ:
- หน้าแรก — แถบ "สถานีที่ใช้ซ้อม"
- แผงแบรนด์หน้า login — ลายจางๆ ที่ opacity 5.5%
- หน้าที่ยังไม่มีข้อมูล — แทนไอคอนทั่วไป

**ทำไมวาดเองแทนใช้ภาพจากภายนอก:** ภาพสต็อกและภาพนักกีฬาเกือบทั้งหมดมีลิขสิทธิ์
และ HYROX เป็นเครื่องหมายการค้าจดทะเบียน การนำโลโก้หรือภาพแบรนด์มาใช้บนเว็บที่ให้บริการลูกค้า
มีความเสี่ยงทางกฎหมาย งานวาดเองจึงปลอดภัยกว่า ไฟล์เล็กกว่า และเปลี่ยนสีตามธีมได้

**ถ้าต้องการไฟล์ PNG** (เช่นเอาไปทำสติกเกอร์ LINE หรืองานพิมพ์) ต้องติดตั้งตัวแปลงก่อน
เพราะ ImageMagick บนเครื่องนี้ยังไม่มี `rsvg-convert`:

```bash
brew install librsvg
```

จากนั้น:

```bash
cd public/img/stations && for f in *.svg; do magick -background none -density 600 "$f" -resize 512x512 "${f%.svg}.png"; done
```

สำหรับใช้บนเว็บ SVG ดีกว่า PNG อยู่แล้ว เพราะคมทุกความละเอียดและเปลี่ยนสีได้

## สีประจำกลุ่มลูกทีม

`member_groups.color` เก็บคีย์สีที่เทรนเนอร์เลือกเอง ชุดสีอยู่ใน `App\Support\GroupPalette`
มี 8 สี **คุมความสว่างและความอิ่มสีให้เท่ากันทุกตัว ต่างกันแค่สีสัน** จึงดูเป็นชุดเดียวกัน

ใช้ผ่าน `$group->palette()` ซึ่งคืนค่าเสมอถึงคีย์ในฐานข้อมูลจะเป็นค่าเก่าที่ถอดออกแล้ว

ป้ายกลุ่มบนการ์ดลูกทีม ทำให้แยกกลุ่มได้ด้วยสายตาโดยไม่ต้องอ่านชื่อ

## รูปโปรไฟล์

`users.avatar_path` เก็บ path ในดิสก์ `public` ใช้ผ่าน `<x-avatar :user="..." />`
ซึ่งถอยไปแสดงตัวอักษรแรกของชื่อเมื่อยังไม่มีรูป

อัปโหลดได้สองที่:
- `/profile` — ผู้ใช้อัปโหลดรูปตัวเอง บันทึกทันทีที่เลือกไฟล์
- `/trainer/team` — เทรนเนอร์แตะที่รูปลูกทีมเพื่อเปลี่ยนได้ เพราะหน้างานมักถ่ายรูปให้ตอนสมัคร
  (ตั้งได้เฉพาะคนที่อยู่ในทีมตัวเอง ตรวจใน `TeamRoster::updatedPhotos()`)

ไฟล์เดิมถูกลบทิ้งทุกครั้งที่เปลี่ยนรูป ผ่าน `App\Services\AvatarService`
ไม่งั้นไฟล์ขยะจะค้างสะสม

**`User::avatarUrl()` คืน path แบบสัมพัทธ์ (`/storage/...`) ตั้งใจไม่ใช้ `Storage::url()`**
เพราะเมธอดนั้นเติม `APP_URL` ไว้ข้างหน้า ถ้า `APP_URL` ตั้งไม่ตรงกับที่เปิดใช้จริง
(เช่นคนละพอร์ต) รูปจะแตกทั้งระบบ ส่วน `<img src>` ไม่จำเป็นต้องเป็น URL เต็มอยู่แล้ว

ต้องรัน `php artisan storage:link` หนึ่งครั้งหลัง clone

## สมัครเอง อนุมัติการสมัคร แล้วจองเอง

**คัดคนตั้งแต่ตอนสมัคร ไม่ใช่ทีละการจอง** คนทั่วไปสมัครที่ `/register` แล้วได้สถานะ
`pending` (รออนุมัติ) เข้าสู่ระบบได้แต่เห็นแค่หน้าสถานะการสมัคร พอแอดมินอนุมัติแล้ว
จองยิมที่ `/member/book` ได้ทันที

| ใคร | ต้องรออนุมัติการสมัครไหม |
|---|---|
| คนทั่วไปที่สมัครที่ `/register` | ต้อง (ปิดได้ด้วย `GYM_REGISTRATION_APPROVAL=false`) |
| ลูกทีมที่เข้าผ่านลิงก์ชวนของเทรนเนอร์ | ไม่ต้อง เทรนเนอร์รับรองตัวคนให้แล้ว |
| เทรนเนอร์ | ต้อง เป็นขั้นตอนเดิมของเทรนเนอร์อยู่แล้ว |

กันไว้สองชั้น `EnsureMemberIsApproved` พาคนที่ยังไม่อนุมัติไปหน้าสถานะ
และ `ReservationService` ไม่ยอมใส่คนที่ยังไม่อนุมัติลงการจอง ไม่ว่าใครจะเป็นคนจอง

## สถานะการจองและเงิน

| สถานะการจอง | ความหมาย |
|---|---|
| รอชำระเงิน | กันเวลาไว้แล้ว ต้องชำระภายใน 30 นาที (หรือก่อนเวลาเริ่ม ถ้าเร็วกว่า) |
| ยืนยันการจอง | ชำระสำเร็จแล้ว |
| หมดอายุ | ไม่ชำระทันเวลา ช่วงเวลาถูกปล่อยให้คนอื่นจองแล้ว |
| ยกเลิก | แอดมินยกเลิก ปล่อยเวลาคืนทันที |

สถานะคืนเงินแยกจากสถานะการจอง: **รอคืนเงิน** · **คืนเงินสำเร็จ** · **คืนเงินไม่สำเร็จ**

ระหว่างที่ยังไม่เปิด Omise (`GYM_PAYMENT_DRIVER=manual`) ผู้ชำระเห็นวิธีโอนจากหน้าแก้ไขสาขา
แล้วแอดมินกด **บันทึกรับชำระ** ที่หน้าการจอง ยอดต้องตรงกับราคาการจอง
พอเปิด Omise ผู้ชำระสแกน QR พร้อมเพย์ที่หน้าการจองได้เลย หน้าเช็คผลเองทุกไม่กี่วินาที
ตั้ง webhook ใน Omise Dashboard เป็น `https://<โดเมน>/webhooks/omise`

ไม่มีปุ่มให้ Trainee ยกเลิกเอง และไม่มีบทลงโทษไม่มาตามนัด จนกว่าเจ้าของระบบจะกำหนดนโยบาย (ข้อ 13)

## ค่าที่ยังรอยืนยันจากเจ้าของระบบ (ข้อ 13)

ทีมพัฒนาไม่ได้ตัดสินเอง ใช้ข้อเสนอในเอกสารเป็นค่าตั้งต้น และเปลี่ยนได้ใน `.env` โดยไม่ต้องแก้โค้ด

| เรื่อง | ค่าตั้งต้น | ตัวตั้งค่า |
|---|---|---|
| จองก่อนเริ่มไม่ถึง 30 นาที | หมดเวลาชำระเมื่อถึงเวลาเริ่ม | `GYM_HOLD_ENDS_AT_START` |
| กลุ่มที่ไม่มี Trainer | ผู้เข้าร่วมทุกคนต้องมีสิทธิ์ | `GYM_NO_TRAINER_RULE=all\|any` |
| เวลากันรอชำระ | 30 นาที | `GYM_HOLD_MINUTES` |
