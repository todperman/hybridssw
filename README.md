## แบ่งหน้าที่หน้าบ้าน / หลังบ้าน

**หน้าบ้านคือตัวโปรดักต์** เทรนเนอร์สมัครเอง สร้างทีมเอง และจองเอง ไม่ต้องพึ่งเจ้าหน้าที่

| เส้นทาง | ใคร | ทำอะไร |
|---|---|---|
| `/` | ทุกคน | หน้าแรก ทางเข้าสมัคร |
| `/register/trainer` | เทรนเนอร์ | สมัครเข้าระบบเอง เลือกประเภทภายใน/ภายนอก |
| `/trainer/schedule` | เทรนเนอร์ | จองรอบให้ลูกทีม ยกเลิก ต่อคิวสำรอง (สลับได้ระหว่างไทม์ไลน์รายวันกับตารางทั้งสัปดาห์) |
| `/trainer/team` | เทรนเนอร์ | ลิงก์/QR ชวนลูกทีม จัดการทีม และสร้างกลุ่มลูกทีม |
| `/trainer/insights` | เทรนเนอร์ | สถิติความหนาแน่นการจอง ทั้งของทีมตัวเองและของสาขา |
| `/team/join/{token}` | ลูกทีม | สมัครเข้าทีมเอง พร้อมเซ็น PAR-Q |
| `/member/bookings` | ลูกทีม | ดูคิว ยืนยันสิทธิ์ ยกเลิก |

**หลังบ้าน (`/admin`) มีหน้าที่ config และกำกับดูแล ไม่ใช่ที่ทำงานประจำวัน**

| ส่วน | สร้างได้ | แก้ไขได้ | หมายเหตุ |
|---|---|---|---|
| สาขา, ตารางเวลาเปิด, วันหยุด, แพ็กเกจ, ผู้ใช้ระบบ | ใช่ | ใช่ | นี่คืองาน config จริง |
| เทรนเนอร์ | **ไม่** | ใช่ | สมัครเองที่หน้าบ้าน หลังบ้านอนุมัติและตั้งโควตา |
| กลุ่มลูกทีม | **ไม่** | ใช่ | เทรนเนอร์สร้างเอง หลังบ้านตั้งเพดานจำนวนสมาชิก |
| ลูกทีม | **ไม่** | ใช่ | เข้าผ่านลิงก์ชวน หลังบ้านดูแลสถานะและแพ็กเกจ |
| รอบการเล่น | **ไม่** | **ไม่** | สร้างจากตารางเวลาเปิด ปรับที่นั่ง/ปิดรอบผ่านปุ่มเฉพาะ |
| การจอง | **ไม่** | **ไม่** | เกิดที่หน้าบ้าน หลังบ้านเช็คอิน/บันทึกไม่มาตามนัด/ยกเลิก |

ข้อจำกัดนี้บังคับด้วย `canCreate()` / `canEdit()` บน Resource และตัด route `create` / `edit` ออกจริง
ไม่ใช่แค่ซ่อนปุ่ม

## ธีมและแบรนด์

ฟอนต์ **IBM Plex Sans Thai** (เนื้อความ) คู่กับ **Plus Jakarta Sans** (หัวข้อ)

พาเลตต์เป็น indigo + น้ำเงิน + มิ้นต์ บนออฟไวท์
สีตั้งต้นที่กำหนดไว้คือ `#464b71` `#118ab2` `#7cd5c7` `#f2f2ed`
ส่วนเฉดที่เหลือคำนวณต่อใน OKLCH

ramp หลักของหลังบ้าน (`BrandPalette::Tide`) **ไล่สีสันผ่านทั้งสามสี** แทนที่จะยึดสีสันเดียว
คือเริ่มที่มิ้นต์ในเฉดอ่อน ผ่านน้ำเงินตรงกลาง แล้วจบที่ indigo ในเฉดเข้ม
ทำให้ไล่เฉดใช้สีของแบรนด์ได้ครบทั้งชุด

| โทเคน | ค่า | ใช้ทำอะไร |
|---|---|---|
| `ink` / `muted` | `#292c41` / `#616471` | ตัวอักษรหลัก / ตัวอักษรรอง |
| `brand-light` | `#7cd5c7` | มิ้นต์ เน้นข้อความบนพื้นเข้ม |
| `brand` / `brand-deep` | `#118ab2` / `#00749a` | น้ำเงิน ลิงก์และจุดบอกสถานะ |
| `brand-dark` / `brand-deepest` | `#464b71` / `#272b49` | indigo พื้นหลังส่วนหัวและปุ่มหลัก |
| `accent-light` / `accent` / `accent-deep` / `accent-ink` | `#f9e5c7` / `#deae67` / `#bd8638` / `#96621e` | อำพัน ใช้กับสถานะที่ต้องเตือน |
| `paper` / `mist` / `line` | `#f2f2ed` / `#e3f0ee` / `#d3dddb` | พื้นหลังและเส้น |
| `track` | `#e8e8e4` | แถบที่ยังไม่ถูกใช้ เช่นช่องที่นั่งว่าง |

โทน `accent` ไม่ได้อยู่ในสี่สีที่กำหนดมา แต่จำเป็นต้องมี เพราะสีที่กำหนดเป็นโทนเย็นทั้งหมด
จึงไม่มีสีไหนที่ผู้ใช้อ่านออกว่าเป็นคำเตือน

หน้าบ้านใช้โทเคนเหล่านี้ผ่าน `tailwind.config.js` ส่วนหลังบ้านใช้ `app/Support/BrandPalette.php`

**ถ้าจะเปลี่ยนพาเลตต์อีก** ต้องแก้ให้ครบทั้ง 5 จุด ไม่งั้นจะมีสีเก่าหลงเหลือ:
`tailwind.config.js` · `resources/css/app.css` (ตัวแปร `:root`) · `app/Support/BrandPalette.php`
(ramp ของ Filament) · ค่าสีที่ฝังตรงในไฟล์ SVG กับไล่เฉด (โลโก้, `public/favicon.svg`,
คลื่นใน `layouts/auth`, hero ของแต่ละหน้า) · `theme-color` ใน `partials/head.blade.php`

**ทำไมไม่ใช้ `Color::hex()` ของ Filament:** ตัวสร้างพาเลตต์อัตโนมัติเร่งความอิ่มสีจนได้ chroma
สูงกว่าสีจริงของแบรนด์หลายเท่า ทำให้หลังบ้านดูสดผิดโทนเมื่อเทียบกับหน้าบ้าน
`BrandPalette` จึงกำหนด ramp แบบ OKLCH เองโดยยึดสีที่กำหนดไว้เป็นหมุด

สีสถานะก็คุมความอิ่มสีให้อยู่ระดับใกล้เคียงกัน: `Leaf` สำหรับสำเร็จ (เขียวเข้มกว่าเซจของแบรนด์
เพื่อให้แยกออก) `Gold` สำหรับเตือน และ `Clay` สำหรับอันตราย

### หน้า auth (login / สมัคร / เข้าร่วมทีม)

ทั้งสามหน้าใช้ `resources/views/layouts/auth.blade.php` ร่วมกัน เป็นเลย์เอาต์สองคอลัมน์
ฝั่งซ้ายเป็นแผงแบรนด์ (ซ่อนต่ำกว่า `lg`) ฝั่งขวาเป็นฟอร์ม แต่ละหน้าส่งข้อความของตัวเองเข้ามา
ผ่าน `->layout('layouts.auth', [...])`

**เส้นแบ่งแบบคลื่น** เป็น SVG สามชั้นที่เลื่อนขึ้นด้วยความเร็วต่างกันเพื่อให้เกิดมิติ
เส้นคลื่นถูกวาดยาวเกินกรอบทั้งบนและล่าง และแอนิเมชันเลื่อนขึ้นครบ 1 รอบพอดี (400 หน่วยใน viewBox)
ภาพจึงต่อกันสนิทและวนได้โดยไม่เห็นรอยต่อ — ถ้าจะแก้ค่ารอบ ต้องแก้ทั้งใน path และใน
`@keyframes wave-scroll` ให้ตรงกัน ไม่งั้นจะเห็นภาพกระตุกทุกครั้งที่วนรอบ

`main` ของเลย์เอาต์นี้ต้องมี `overflow-x-hidden` เสมอ เพราะก้อนแสงตกแต่งล้นขอบขวา
ถ้าเอาออกจะเกิดแถบเลื่อนแนวนอนบนจอเล็ก

**สมัครเทรนเนอร์เป็น wizard 3 ขั้น** (`App\Livewire\TrainerRegistration`) ตรวจทีละขั้นด้วย
`rulesForStep()` และตรวจทั้งหมดอีกครั้งตอนกดสมัคร ผู้ใช้ย้อนกลับไปขั้นที่ผ่านมาแล้วได้
แต่กระโดดข้ามไปข้างหน้าไม่ได้ ส่วนมาตรวัดความแข็งแรงรหัสผ่านคำนวณฝั่งเบราว์เซอร์ด้วย Alpine
เพื่อให้เห็นผลทันทีขณะพิมพ์ ไม่ต้องวิ่งไปเซิร์ฟเวอร์

ทุกแอนิเมชันมี `@media (prefers-reduced-motion: reduce)` ปิดให้อัตโนมัติ

### กล่องยืนยันและการแจ้งผล

**ห้ามใช้ `wire:confirm` หรือ `confirm()` ของเบราว์เซอร์** ทั้งโปรเจกต์ใช้กล่องยืนยันของแอปเอง
(`resources/views/components/app-dialog.blade.php`) ซึ่งผูกอยู่กับ `layouts/app` อยู่แล้ว

```blade
<button @click="$store.confirm.ask({
    title: 'ยกเลิกการจอง',
    body: 'ชื่อลูกทีม · 17:00 - 18:00',
    notes: ['ยกเลิกทันเวลา เครดิตจะถูกคืน', 'ที่นั่งจะถูกปล่อยให้คิวสำรอง'],
    tone: 'danger',
    action: () => $wire.cancelBooking(12),
})">ยกเลิก</button>
```

`notes` มีไว้บอกผลกระทบที่ผู้ใช้ควรรู้ก่อนกดยืนยัน เช่น จะโดนหักเครดิตหรือไม่
ซึ่ง `confirm()` ของเบราว์เซอร์ทำไม่ได้

**การแจ้งผลใช้ toast ไม่ใช่ flash message** ฝั่ง Livewire เรียก
`$this->dispatch('toast', tone: 'success', title: '...', body: '...')`
โดย `tone` รับค่า success / error / warning / info ฝั่ง JS ล้วนๆ ก็ยิง
`window.dispatchEvent(new CustomEvent('toast', { detail: {...} }))` ได้เหมือนกัน

### ชื่อผู้ใช้

ตาราง `users` เก็บ `first_name` กับ `last_name` แยกกัน ส่วน `name` เป็น
**stored generated column** ที่ MySQL คำนวณให้เองจากสองคอลัมน์นั้น

```sql
name  VARCHAR(255)  GENERATED ALWAYS AS (TRIM(CONCAT_WS(' ', first_name, last_name))) STORED
```

เลือกวิธีนี้แทนการทำ accessor ใน PHP เพราะยังค้นหาและเรียงลำดับด้วย `name` ใน SQL ได้ตรงๆ
(Filament ใช้ความสามารถนี้) และไม่ต้องเขียนโค้ดซิงก์เอง

**`name` เขียนไม่ได้** ถ้าโค้ดไหนพยายาม `update(['name' => ...])` MySQL จะโยน error ทันที
ให้เขียนที่ `first_name` / `last_name` แทน มีเทสต์ใน `tests/Feature/UserNameTest.php` คุมไว้

## โจทย์หลักที่ระบบนี้แก้

- แต่ละรอบรับได้สูงสุด **5 คน ไม่รวมเทรนเนอร์** ปรับรายรอบได้
- เปิด-ปิดเวลาได้ตามที่กำหนด รวมถึงวันหยุดและเวลาพิเศษ
- **เทรนเนอร์ต้องสมัครก่อน** แล้วหาลูกทีมมาเล่นเอง
- เทรนเนอร์มี 2 ประเภท: **ภายใน** และ **ภายนอก** ซึ่งมีสิทธิ์ต่างกันจริง ไม่ใช่แค่ป้ายกำกับ
- รองรับหลายสาขา (multi-branch) ตั้งแต่โครงสร้างฐานข้อมูล
- หลังบ้านสำหรับตั้งค่าและกำกับดูแล

## ติดตั้งบนเครื่องพัฒนา

```bash
cp .env.example .env
composer install
npm install

php artisan key:generate
php artisan migrate --seed          # DatabaseSeeder = ข้อมูลตัวอย่างสำหรับทดลอง
php artisan storage:link            # ให้รูปโปรไฟล์ใน storage เปิดผ่านเว็บได้
php artisan filament:assets

npm run build                       # หรือ npm run dev ระหว่างพัฒนา
php artisan serve --port=8210
```

บัญชีตัวอย่างจาก `DatabaseSeeder` ใช้รหัส `password` ทุกบัญชี
**ห้ามรัน seeder ตัวนี้บนเซิร์ฟเวอร์จริง**

## ขึ้นเซิร์ฟเวอร์จริง

ความต้องการขั้นต่ำ: PHP 8.2 (พัฒนาและทดสอบบน 8.4 — ต้องมี `ext-intl` สำหรับรูปแบบเงินบาทและวันที่ภาษาไทย),
MySQL 8, Composer, Node 20+ สำหรับ build ไฟล์ครั้งเดียว

### ครั้งแรก

```bash
git clone <repo> hybridssw && cd hybridssw

cp .env.example .env
# แก้ .env: APP_ENV=production, APP_DEBUG=false, APP_URL=https://โดเมนจริง
#           ตั้งค่า DB_*, MAIL_* และตั้ง ADMIN_EMAIL / ADMIN_PASSWORD ไว้ชั่วคราว

composer install --no-dev --optimize-autoloader
npm ci && npm run build

php artisan key:generate
php artisan migrate --force
php artisan db:seed --class=ProductionSeeder --force   # สาขาแรก + บัญชีแอดมิน ไม่มีข้อมูลตัวอย่าง
php artisan storage:link
php artisan filament:assets

php artisan config:cache
php artisan route:cache
php artisan view:cache
```

จากนั้น **ลบ `ADMIN_PASSWORD` ออกจาก .env** แล้วเข้า `/admin` ไปตั้งค่าสาขา
เทมเพลตตาราง และแพ็กเกจต่อ

### ทุกครั้งที่ deploy รอบถัดไป

```bash
php artisan down
git pull
composer install --no-dev --optimize-autoloader
npm ci && npm run build
php artisan migrate --force
php artisan filament:assets
php artisan optimize          # cache config/route/view ใหม่ทั้งหมด
php artisan up
```

### ถ้าเซิร์ฟเวอร์เป็น Windows + IIS

IIS ไม่อ่าน `.htaccess` ใช้ `public/web.config` ที่มีมาให้ในโปรเจกต์แทน
ต้องติดตั้ง **URL Rewrite Module** ของ IIS ก่อน ไม่งั้นทุก URL นอกจากหน้าแรกจะ 500

- PHP ต้องเป็นรุ่น **NTS (Non-Thread-Safe) x64** เพราะ IIS ต่อผ่าน FastCGI
- เปิด extension ใน `php.ini`: `intl` `mbstring` `openssl` `pdo_mysql` `fileinfo` `curl` `zip` `gd`
- ตั้ง `cgi.fix_pathinfo=1` และ `fastcgi.impersonate=1`
- Physical path ของ site ต้องชี้ที่ `public\` เท่านั้น
- ให้สิทธิ์ Modify แก่ `IIS AppPool\<ชื่อ pool>` บน `storage\` และ `bootstrap\cache\`
- `php artisan storage:link` ต้องรันจาก PowerShell ที่เปิดแบบ Run as administrator
  เพราะการสร้าง symlink บน Windows ต้องใช้สิทธิ์ผู้ดูแล
- แทน cron ให้ใช้ Task Scheduler รัน `php artisan schedule:run` ทุก 1 นาที
- แทน supervisor ให้ทำ queue worker เป็น Windows Service ด้วย NSSM

### สิ่งที่ต้องตั้งเพิ่มบนเซิร์ฟเวอร์

**เว็บเซิร์ฟเวอร์** ชี้ document root ไปที่ `public/` เท่านั้น
และให้ `storage/` กับ `bootstrap/cache/` เขียนได้โดยผู้ใช้ของ PHP-FPM

**ตัวจับเวลา** — ระบบมีงานอัตโนมัติ (สร้างรอบล่วงหน้า ปล่อยคิวสำรองที่หมดเวลา
ปลดล็อกสมาชิกที่ถูกระงับครบกำหนด) ต้องมี cron บรรทัดเดียวนี้

```cron
* * * * * cd /path/to/hybridssw && php artisan schedule:run >> /dev/null 2>&1
```

**คิวงาน** — `QUEUE_CONNECTION=database` ต้องมีตัวรันค้างไว้ เช่นผ่าน supervisor

```bash
php artisan queue:work --sleep=3 --tries=3 --max-time=3600
```

**เวลาและภาษา** — `APP_TIMEZONE=Asia/Bangkok` และ `APP_LOCALE=th` ต้องตรงกับในฐานข้อมูล
ไม่งั้นเวลารอบจะเพี้ยนข้ามวัน

### ฐานข้อมูล

โครงสร้างทั้งหมดอยู่ใน `database/migrations` ไม่ต้องนำเข้าไฟล์ dump
เซิร์ฟเวอร์ใหม่รัน `migrate --force` แล้วได้โครงครบทันที

มีสอง seeder ที่ทำคนละหน้าที่

| Seeder | ใช้เมื่อไร | สร้างอะไร |
|---|---|---|
| `DatabaseSeeder` | เครื่องพัฒนาเท่านั้น | สาขา เทรนเนอร์ ลูกทีม รอบ และการจองตัวอย่าง รหัสผ่าน `password` |
| `ProductionSeeder` | เซิร์ฟเวอร์จริง | สาขาแรกกับบัญชีแอดมินหนึ่งคน อ่านรหัสจาก `.env` รันซ้ำได้ไม่สร้างซ้ำ |

## สิ่งที่ห้ามแก้โดยไม่เข้าใจ

### 1. การกันจองเกิน

`booked_count` บนตาราง `workout_sessions` คือตัวเลขที่ถือว่าเชื่อถือได้ และถูกอ่าน/เขียน
**ภายใต้ `lockForUpdate()` บนแถวรอบเท่านั้น** (`app/Services/BookingService.php`)

ห้ามคำนวณที่ว่างจาก `COUNT(*)` นอกล็อก เพราะสองคำขอที่เข้ามาพร้อมกันจะเห็นที่นั่งว่างใบเดียวกัน
แล้วจองทะลุ capacity ข้อนี้มีเทสต์คุมอยู่ และเคยพิสูจน์ด้วยการยิง 6 โปรเซสพร้อมกันแล้ว

ด่านสุดท้ายคือ unique index `(workout_session_id, active_member_key)`
คอลัมน์ `active_member_key` เท่ากับ `member_id` ตอนการจองยัง active และเป็น `NULL` เมื่อยกเลิก
MySQL ยอมให้ `NULL` ซ้ำกันในคีย์ unique ลูกทีมจึงจองรอบเดิมใหม่หลังยกเลิกได้
แต่จองซ้อนในรอบเดียวกันตอน active ไม่ได้ (MySQL ไม่มี partial index จึงต้องใช้วิธีนี้)

### 2. ตารางเวลา 3 ชั้น

ไม่เก็บทุกชั่วโมงล่วงหน้าเป็นปี แต่ใช้:

1. `schedule_templates` — กฎเวลาเปิดประจำสัปดาห์
2. `schedule_exceptions` — วันหยุด / เปลี่ยนเวลา / เปิดรอบพิเศษ ทับกฎข้างบน
3. `workout_sessions` — รอบจริงที่ `SessionGenerator` สร้างล่วงหน้าตาม `session_horizon_days`

แอดมินแก้เวลาเปิด-ปิดได้โดยไม่กระทบการจองที่มีอยู่แล้ว

### 3. ตาราง `workout_sessions` ไม่ใช่ `sessions`

Laravel ใช้ชื่อ `sessions` สำหรับ session driver แบบ database อยู่แล้ว

### 4. Blade: ใช้ php แบบบรรทัดเดียวเท่านั้น

`@php(...)` กับรูปแบบบล็อกปนกันในไฟล์เดียวไม่ได้ Blade จับคู่ด้วย regex แบบ non-greedy แล้วจะคอมไพล์ผิด

## เทรนเนอร์ 2 ประเภทต่างกันอย่างไร

| | ภายใน | ภายนอก |
|---|---|---|
| การอนุมัติ | อัตโนมัติ (ต้องมีรหัสพนักงาน) | แอดมินตรวจเอกสารก่อน |
| ที่นั่งต่อรอบ | 5 | 3 |
| จองล่วงหน้า | 30 วัน | 7 วัน |
| ขนาดทีม | 50 | 20 |
| ใบรับรอง | ไม่บังคับ | บังคับ หมดอายุแล้วถูกบล็อกทันที |

ค่าในตารางเป็น **ค่าเริ่มต้นที่ตั้งได้ใน `config/gym.php`** (ผ่าน `.env`) ไม่ได้ฝังไว้ในโค้ด
และแอดมินยังตั้งทับรายคนได้อีกชั้นที่หน้าแก้ไขเทรนเนอร์

```
GYM_EXTERNAL_SEATS=5          GYM_INTERNAL_SEATS=5
GYM_EXTERNAL_ADVANCE_DAYS=7   GYM_INTERNAL_ADVANCE_DAYS=30
GYM_EXTERNAL_MAX_TEAM=20      GYM_INTERNAL_MAX_TEAM=      # เว้นว่าง = ไม่จำกัด
```

**`max_team_size` เป็น null แปลว่าไม่จำกัด** `Trainer::maxTeamSize()` จึงคืน `?int`
ถ้าเขียนโค้ดที่เทียบกับค่านี้ ต้องเช็ค null ก่อนเสมอ ไม่งั้นทีมไม่จำกัดจะถูกบล็อกทันที
ใช้ `hasUnlimitedTeam()` กับ `teamLimitLabel()` ช่วยได้

## ตัวเลือกของหน้าสมัครเทรนเนอร์

```
GYM_REGISTRATION_SHOW_BRANCH=true       # แสดงตัวเลือกสาขา
GYM_REGISTRATION_VERIFY_IDENTITY=true   # บังคับยืนยันตัวตน
```

**ตัวเลือกสาขา** ปิดแล้วจะไม่แสดง และระบบผูกสาขาที่เปิดใช้งานอันแรกให้อัตโนมัติ
นอกจากนี้ถ้ามีสาขาเดียวก็ไม่แสดงอยู่แล้วถึงจะเปิดค่านี้ไว้

**การยืนยันตัวตน** ปิดแล้วขั้นตอนที่ 3 จะหายไปทั้งขั้น เหลือ 2 ขั้น
และ **เทรนเนอร์ภายในจะไม่ถูกอนุมัติอัตโนมัติอีกต่อไป** เพราะไม่มีอะไรยืนยันว่าเป็นพนักงานจริง
ทุกคนจะเข้าคิวรอแอดมินตรวจแทน — จุดนี้สำคัญ ถ้าปล่อยให้อนุมัติอัตโนมัติทั้งที่ไม่ตรวจอะไรเลย
ใครก็สมัครเป็นเทรนเนอร์ภายในแล้วจองได้ทันที

ในหน้าสมัคร **เทรนเนอร์ภายนอกแสดงเป็นลำดับแรก** เพราะเป็นกลุ่มที่สมัครเองเป็นหลัก
(`TrainerType::orderedForRegistration()` ส่วนหลังบ้านยังใช้ลำดับปกติของ enum)

## หน้าหมดอายุ (419)

หน้าที่เปิดค้างไว้นานจนเซสชันหมดอายุ แล้วกดส่งฟอร์ม เดิมจะเจอหน้า `419 PAGE EXPIRED` เปล่าๆ

พร้อมข้อความให้กดส่งอีกครั้ง และคงค่าที่กรอกไว้ (ยกเว้นรหัสผ่าน)

## สองมุมมองของหน้าจอง

สลับได้ที่แถบเลือกวัน และจำค่าไว้ข้ามหน้าเพราะเป็นความชอบส่วนตัว (`#[Session]`)

| มุมมอง | เหมาะกับ |
|---|---|
| ไทม์ไลน์ | ดูรายวันละเอียด เห็นชื่อลูกทีมในแต่ละรอบ |
| ตารางสัปดาห์ | หาช่องว่างข้ามวัน แตะช่องเพื่อจองได้เลย |

### ตัวกรอง "การจองของฉัน"

ปุ่มบนแถบเลือกวัน กรองให้เหลือเฉพาะรอบที่เทรนเนอร์คนนั้นจองไว้
ใช้ได้ทั้งสองมุมมอง และกรองที่ระดับคิวรีด้วย `whereHas` ไม่ได้กรองหลังดึงมาทั้งหมด

ตั้งใจ **ไม่จำค่าข้ามหน้า** ต่างจากตัวเลือกมุมมอง เพราะตัวกรองที่ซ่อนข้อมูลไว้ข้ามวัน
จะทำให้ผู้ใช้งงว่าทำไมตารางว่าง ส่วนตัวเลือกมุมมองไม่ได้ซ่อนอะไรจึงจำไว้ได้

ป้ายสถิติบนหัวหน้าและข้อความตอนไม่มีข้อมูลเปลี่ยนตามตัวกรองด้วย
(`รอบวันนี้` → `รอบของคุณวันนี้`, `วันนี้ไม่มีรอบเปิดให้จอง` → `วันนี้คุณยังไม่ได้จองรอบไหน`)
ไม่งั้นตัวเลขและข้อความจะอ่านผิดความหมาย

**ข้อควรระวัง:** `selectedSession` ต้องดึงรอบจากฐานข้อมูลตรงๆ ไม่ใช่หาจากรายการของวันที่กำลังดู
เพราะในมุมมองตารางผู้ใช้กดช่องของวันอื่นได้ ถ้าหาจากรายการของวันนั้นจะได้ null แล้วกล่องจองไม่เปิด

## กลุ่มลูกทีม

เทรนเนอร์สร้างกลุ่มเองได้ที่ `/trainer/team` เช่น "กลุ่มเช้า จ-พ-ศ" แล้วจองทั้งกลุ่ม
ลงรอบเดียวได้ในคลิกเดียวจากหน้าตารางจอง

**จำนวนสมาชิกสูงสุดต่อกลุ่มเป็นของแอดมิน เทรนเนอร์แก้ไม่ได้**

| ระดับ | ตั้งที่ไหน | ผล |
|---|---|---|
| ทั้งสาขา | หน้าแก้ไขสาขา → `จำนวนลูกทีมสูงสุดต่อกลุ่ม` | เพดานเริ่มต้นของทุกกลุ่มในสาขา |
| รายกลุ่ม | หน้า `กลุ่มลูกทีม` ในหลังบ้าน → `จำกัดเฉพาะกลุ่มนี้` | ตั้งทับเฉพาะกลุ่มนั้น เว้นว่าง = ใช้ค่าของสาขา |

หลังบ้าน **สร้างกลุ่มเองไม่ได้และลบไม่ได้** ทำได้แค่ตั้งเพดานและเปิด/ปิดกลุ่ม
ตรงตามหลักที่ว่าหน้าบ้านคือที่ทำงาน หลังบ้านคือที่ตั้งค่า

กติกาอยู่ใน `App\Services\MemberGroupService` ทั้งหมด:

- สมาชิกกลุ่มต้องอยู่ในทีมของเทรนเนอร์คนนั้นก่อน
- เพิ่มเกินเพดานไม่ได้ (ล็อกแถวกลุ่มก่อนนับ กันการเพิ่มพร้อมกันทะลุเพดาน)
- ลูกทีมอยู่ได้หลายกลุ่ม แต่ซ้ำกลุ่มเดิมไม่ได้
- เทรนเนอร์แตะกลุ่มของคนอื่นไม่ได้
- ลบกลุ่มแล้วลูกทีมยังอยู่ในทีมตามเดิม และการจองที่ทำไปแล้วไม่ถูกกระทบ

ตอนกดเลือกทั้งกลุ่มในหน้าจอง ระบบจะข้ามคนที่จองรอบนั้นไปแล้ว และถ้าที่นั่งเหลือน้อยกว่าจำนวนคน
จะเลือกให้เท่าที่นั่งว่างแทนที่จะดันทั้งกลุ่มเข้าคิวสำรอง เว้นแต่ติ๊กเปิดคิวสำรองไว้

ชุดอุปกรณ์ซ้อมใน `resources/views/components/station-icon.blade.php` และไฟล์เดี่ยวที่

ใช้ `currentColor` จึงเปลี่ยนสีตามบริบทที่วางได้เลย

วางไว้ 3 จุดเท่านั้น ตั้งใจไม่ใส่เยอะ:
- หน้าแรก — แถบ "สถานีที่ใช้ซ้อม"
- แผงแบรนด์หน้า login — ลายจางๆ ที่ opacity 5.5%
- หน้าที่ยังไม่มีข้อมูล — แทนไอคอนทั่วไป

และ HYROX เป็นเครื่องหมายการค้าจดทะเบียน การนำโลโก้หรือภาพแบรนด์มาใช้บนเว็บที่ให้บริการลูกค้า
มีความเสี่ยงทางกฎหมาย งานวาดเองจึงปลอดภัยกว่า ไฟล์เล็กกว่า และเปลี่ยนสีตามธีมได้

**ถ้าต้องการไฟล์ PNG** (เช่นเอาไปทำสติกเกอร์ LINE หรืองานพิมพ์) ต้องติดตั้งตัวแปลงก่อน
เพราะ ImageMagick บนเครื่องนี้ยังไม่มี `rsvg-convert`:

```bash
brew install librsvg
```

จากนั้น:

```bash
cd public/img/stations && for f in *.svg; do magick -background none -density 600 "$f" -resize 512x512 "${f%.svg}.png"; done
```

สำหรับใช้บนเว็บ SVG ดีกว่า PNG อยู่แล้ว เพราะคมทุกความละเอียดและเปลี่ยนสีได้

## สีประจำกลุ่มลูกทีม

ป้ายกลุ่มบนการ์ดลูกทีม ทำให้แยกกลุ่มได้ด้วยสายตาโดยไม่ต้องอ่านชื่อ

## รูปโปรไฟล์

`users.avatar_path` เก็บ path ในดิสก์ `public` ใช้ผ่าน `<x-avatar :user="..." />`
ซึ่งถอยไปแสดงตัวอักษรแรกของชื่อเมื่อยังไม่มีรูป

อัปโหลดได้สองที่:
- `/profile` — ผู้ใช้อัปโหลดรูปตัวเอง บันทึกทันทีที่เลือกไฟล์
- `/trainer/team` — เทรนเนอร์แตะที่รูปลูกทีมเพื่อเปลี่ยนได้ เพราะหน้างานมักถ่ายรูปให้ตอนสมัคร

ไม่งั้นไฟล์ขยะจะค้างสะสม

**`User::avatarUrl()` คืน path แบบสัมพัทธ์ (`/storage/...`) ตั้งใจไม่ใช้ `Storage::url()`**
เพราะเมธอดนั้นเติม `APP_URL` ไว้ข้างหน้า ถ้า `APP_URL` ตั้งไม่ตรงกับที่เปิดใช้จริง
(เช่นคนละพอร์ต) รูปจะแตกทั้งระบบ ส่วน `<img src>` ไม่จำเป็นต้องเป็น URL เต็มอยู่แล้ว

ต้องรัน `php artisan storage:link` หนึ่งครั้งหลัง clone

## ความเป็นส่วนตัวบนหน้าจอง

เทรนเนอร์ **เห็นว่าที่นั่งถูกใช้ไปแล้วกี่ที่ แต่ไม่เห็นว่าเป็นของใคร**

- แถบที่นั่งแยกสามสถานะ: ของคุณ (เข้ม) · ผู้เล่นอื่น (อ่อน) · ว่าง (เทา)
- ลูกทีมของตัวเองแสดงชื่อได้ ส่วนที่นั่งของคนอื่นแสดงเป็นวงกลมไม่ระบุตัวตน
- รอบที่ถูกเหมาไปแล้วบอกแค่ว่า "ถูกเทรนเนอร์ท่านอื่นเหมาไปแล้ว" ไม่บอกชื่อ

มีเทสต์ใน `tests/Feature/SchedulePrivacyTest.php` คุมไว้ว่าชื่อลูกทีมและชื่อเทรนเนอร์ของคนอื่น
จะไม่ปรากฏบนหน้านี้ **ถ้าจะเพิ่มข้อมูลอะไรลงการ์ดรอบ ให้ดูเทสต์ชุดนี้ก่อน**

หลังบ้านเห็นชื่อทุกคนตามปกติ เพราะเป็นบทบาทที่ต้องดูแลข้อมูล

## Heatmap ความหนาแน่นการจอง

`/admin/booking-heatmap` แสดงอัตราการใช้ที่นั่งแยกตามวันในสัปดาห์ x ชั่วโมง
เลือกสาขาและช่วงย้อนหลังได้ (4 / 8 / 12 สัปดาห์ / 6 เดือน)

**สิ่งที่นับ** ไม่ใช่ `booked_count` ปัจจุบัน แต่เป็นจำนวนการจองที่ *เคยกินที่นั่งจริง*
คือสถานะ booked / checked_in / completed / **no_show** เพราะคนที่ไม่มาตามนัด
ก็ยังนับเป็นความต้องการที่เกิดขึ้นจริง ถ้าไม่นับจะประเมินความต้องการต่ำกว่าจริง

**ความต้องการที่ล้น** นับจาก `bookings.waitlist_position` ที่ยังค้างอยู่
เพราะคนที่ถูกเลื่อนขึ้นได้ที่นั่งแล้วจะถูกล้างตำแหน่งคิวทิ้ง เหลือค้างไว้เฉพาะคนที่รอจนจบรอบ
แล้วไม่ได้ที่นั่ง ซึ่งคือความต้องการที่รับไม่ทันจริงๆ

หน้านี้สรุปให้ 3 อย่างที่เอาไปตัดสินใจได้เลย:

| การ์ด | บอกอะไร | เอาไปทำอะไร |
|---|---|---|
| ควรเปิดรอบเพิ่ม | ชั่วโมงที่มีคนรอคิวสำรองจนจบรอบแล้วไม่ได้ที่นั่ง | เปิดรอบเพิ่มหรือเพิ่มที่นั่ง |
| ชั่วโมงที่แน่นที่สุด | อัตราใช้ที่นั่งสูงสุด | จัดกำลังเทรนเนอร์และอุปกรณ์ |
| ว่างเรื้อรัง | เปิดมาแล้ว ≥3 รอบ แต่ใช้ไม่ถึง 1 ใน 3 | ยุบรอบ หรือทำราคาช่วงนอกพีค |

### เทรนเนอร์ก็มีหน้าสถิติของตัวเอง

`/trainer/insights` ใช้ตรรกะเดียวกันผ่าน `App\Services\BookingHeatmapService`
(คิวรีอยู่ที่เดียว หน้าแอดมินกับหน้าเทรนเนอร์จะได้ไม่นิยามตัวเลขหลุดกัน) มีสองมุมมอง:

| มุมมอง | นับอะไร | ใช้ทำอะไร |
|---|---|---|
| ทีมของฉัน | เฉพาะการจองที่เทรนเนอร์คนนั้นทำ | รู้ว่าทีมตัวเองเล่นช่วงไหน ใช้วางตาราง |
| ทั้งสาขา | อัตราการใช้ที่นั่งรวม | รู้ว่าชั่วโมงไหนเต็มเร็ว ต้องจองล่วงหน้าแค่ไหน |

มุมมองทั้งสาขาเป็นเปอร์เซ็นต์ล้วนๆ ไม่มีชื่อใครปรากฏ จึงไม่ขัดกับกติกาความเป็นส่วนตัวข้างบน

### ความกว้างของหน้าในหลังบ้าน

หน้าที่เป็นตารางใช้ความกว้างเต็มจอผ่าน `App\Filament\Concerns\HasFullWidthTable`
ส่วนหน้าฟอร์ม (สร้าง/แก้ไข) คงความกว้างเดิมไว้ที่ 1280px

**ตั้งใจแยกแบบนี้** เพราะตารางมีคอลัมน์เยอะ ยิ่งกว้างยิ่งอ่านง่ายและไม่ต้องเลื่อนแนวนอน
แต่ฟอร์มที่กว้างเต็มจอจะได้บรรทัดยาวเกินจนอ่านยาก และช่องกรอกจะยืดออกจนดูไม่เป็นระเบียบ

ถ้าเพิ่ม resource ใหม่ อย่าลืมใส่ trait นี้ที่หน้า `List...` ด้วย

**หมายเหตุเรื่องสไตล์:** วิวหน้าแอดมินเขียน CSS ไว้ในไฟล์เอง ไม่ได้ใช้คลาส Tailwind
เพราะ Filament ใช้ CSS ที่คอมไพล์มาแล้วและไม่ได้สแกนวิวของโปรเจกต์ ถ้าเขียนด้วยคลาส Tailwind
ตรงนั้นจะไม่มีสไตล์ออกมาเลย

อยากได้ข้อมูลตัวอย่างไว้ดูหน้านี้ ใช้:

```bash
php artisan db:seed --class=DemoHistorySeeder
```

สร้างประวัติย้อนหลัง 10 สัปดาห์ที่มีรูปแบบความต้องการสมจริง (เย็นแน่น เช้ารองลงมา บ่ายเงียบ)
พร้อมคนไม่มาตามนัดราว 10% และคิวสำรองล้นในชั่วโมงพีค

## กติกาการจองที่บังคับใช้

ทุกข้อตรวจใน `BookingService` และมีเทสต์คุม:

- รอบต้องเปิดรับจองและยังไม่เริ่ม
- เทรนเนอร์ต้องอนุมัติแล้ว สัญญายังมีผล ใบรับรองยังไม่หมดอายุ
- ไม่เกินโควตาที่นั่งต่อรอบ และไม่เกินระยะจองล่วงหน้า
- ลูกทีมต้องอยู่ในทีมของเทรนเนอร์คนนั้น
- ลูกทีมต้องเซ็น PAR-Q แล้ว ไม่ถูกระงับสิทธิ์ และมีเครดิตพอ
- ลูกทีมห้ามมีคิวชนเวลากันข้ามรอบ
- เทรนเนอร์ ลูกทีม และรอบ ต้องอยู่สาขาเดียวกัน

## คิวสำรอง เครดิต และการไม่มาตามนัด

- รอบเต็ม → ต่อคิวสำรองได้ **ยังไม่ตัดเครดิต**
- มีคนยกเลิก → เลื่อนคิวแรกขึ้นอัตโนมัติ ตัดเครดิตตอนนั้น และให้เวลายืนยันตาม `waitlist_confirm_minutes`
- ไม่ยืนยันทัน → `bookings:release-unconfirmed` คืนที่นั่งและเลื่อนคนถัดไป
- ยกเลิกก่อน `cancellation_cutoff_hours` → คืนเครดิต หลังจากนั้น → หักเครดิต
- ไม่มาตามนัดครบ `no_show_strike_limit` ครั้ง → ระงับสิทธิ์จอง `no_show_suspension_days` วัน อัตโนมัติ

ค่าทั้งหมดตั้งแยกรายสาขาได้ที่หน้าแก้ไขสาขา

## งานอัตโนมัติ

ต้องมี scheduler ทำงานจริงบนเซิร์ฟเวอร์:

```bash
php artisan schedule:work
```

| คำสั่ง | ความถี่ | หน้าที่ |
|---|---|---|
| `sessions:generate` | ทุกวัน 02:00 | เลื่อนขอบเขตการจองไปข้างหน้า |
| `bookings:release-unconfirmed` | ทุก 5 นาที | คืนที่นั่งของคิวที่ไม่ยืนยัน |
| `sessions:finalize` | ทุก 15 นาที | ปิดรอบที่จบแล้วและบันทึกผู้ไม่มาตามนัด |

ทุกคำสั่งรองรับ `--dry-run` ยกเว้น `sessions:generate` ที่รันซ้ำได้โดยไม่สร้างข้อมูลซ้ำ

## เทสต์

เตรียมฐานทดสอบครั้งเดียว แล้วรันได้เลย

```bash
mysql -e "CREATE DATABASE IF NOT EXISTS hybridssw_test"
php artisan test
```

เทสต์ใช้ MySQL จริง (ฐาน `hybridssw_test`) ไม่ใช่ SQLite เพราะต้องพึ่งพฤติกรรมของ
`lockForUpdate` และ unique key ที่ยอมให้ `NULL` ซ้ำได้ ซึ่ง SQLite ให้ผลไม่เหมือนกัน

`phpunit.xml` เปลี่ยนให้แค่ชื่อฐาน ส่วน host / port / user / password ใช้ของ `.env`
เครื่องนั้น ๆ จึงไม่มีรหัสผ่านของใครฝังอยู่ในไฟล์ที่ขึ้น repo

## ที่ยังไม่ได้ทำ

- แจ้งเตือนผ่าน LINE OA (โครงสร้างพร้อมแล้ว มี `users.line_user_id`)
- หน้าสแกน QR เช็คอินสำหรับเจ้าหน้าที่ (เช็คอินตอนนี้ทำผ่านหลังบ้าน)
- จองซ้ำอัตโนมัติรายสัปดาห์ (recurring booking)
- ขายแพ็กเกจออนไลน์และชำระเงิน (ตอนนี้แอดมินออกแพ็กเกจให้)
- รายงานเชิงลึก เช่น heatmap ชั่วโมงที่คนแน่น และ cohort การกลับมาใช้บริการ
